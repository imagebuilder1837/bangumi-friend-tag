# cloud_settings 单键存储 + localStorage 缓存优先 + 后台按好友合并

好友标签数据需要跨设备云同步，但 `chiiApp.cloud_settings` 只能在脚本启动后读取，且保存无回调/无失败通知。我们决定（本 ADR 的适用范围后经 ADR-0003 收窄为**仅超合金组件模式**）：所有标签存放在 cloud_settings 的**单个键**里（整张 `{用户标识: 标签数组}` 映射），启动时先用 localStorage 缓存渲染、后台请求云端数据，到达后做**按好友条目合并**（本地编辑过的好友条目优先，其余以云端为准）并回写云端。多标签页并发接受 last-write-wins。

## Considered Options

- **每好友一个 cloud_settings 键**：合并语义天然，但已知 bug「无法删除最后一个 key」，且键数量随好友增长、导入导出需遍历，故放弃。
- **启动时阻塞等待云端数据**：渲染延迟不可接受，故采用缓存优先。
- **云端到达后整体覆盖**：会丢失刷新窗口期内的本地编辑，故改为按好友合并。

## Consequences

- localStorage 键与 cloud_settings 键内的映射结构必须保持一致，演进 schema 时需同时迁移两处。
- 若合并期间检测到本地有待写编辑，需在合并后调用 `update + save` 回写云端，否则编辑会随下次刷新丢失。
